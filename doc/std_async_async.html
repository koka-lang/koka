Asynchronous primitives.

This module is based closely on [1] and aims to have robust and composable asynchronous primitives. In particular, any outstanding asynchronous operation can be canceled (through cancel-outstandingstd/async/async/cancel-outstanding: () -> async-cancel ()) within a certain cancelation scope which allows for composable primitives like timeout and interleave.

1. Cancelation

When calling cancel-outstandingstd/async/async/cancel-outstanding: () -> async-cancel (), it cancels any outstanding async operations in the current cancelation scope and any of its child scopes. Some reasons for cancelation: - returning normally, cancelation prevents dangling callbacks - returning abnormally (e.g. an exception), we cancel any pending callbacks - within a firstof, we have decided to cancel all remaining strands after the first is one completes

After cancel-outstandingstd/async/async/cancel-outstanding: () -> async-cancel () is called, the caller continues as normal - calling cancel-oustanding simply returns ().

The way that cancelation is observed is that all outstanding async operaions in the cancelation scope receive a Cancelstd/async/internal/Cancel: forall<a> await-result<a> result instead of a Resultstd/async/internal/Result: forall<a> (value : a) -> await-result<a> (or Exception). Aside from low-level code, a user won't observe this as the abstractions awaiting a result automatically use discontinuestd/async/async/discontinue: forall<a> () -> discontinue a() when Cancelstd/async/internal/Cancel: forall<a> await-result<a> a result is given.

We use a separate effect discontinuestd/async/async/discontinue: (E, V) -> V instead of an exception since it is intended that a discontinuestd/async/async/discontinue: forall<a> () -> discontinue a is never handled and always discontinues a stsrand. Of course, finallystd/core/hnd/finally: forall<a,e> (fin : () -> e (), action : () -> e a) -> e a blocks still execute so external resources can be released properly.
